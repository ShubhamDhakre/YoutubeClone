1. PROJECT OVERVIEW & TECH STACK
================================================================================
This is a production-grade, enterprise-modeled backend API for a YouTube-like
video hosting and social media platform. It implements secure user authentication
using dual JSON Web Tokens (Access + Refresh tokens) stored in HTTP-only cookies,
media upload management through Multer and Cloudinary, MongoDB aggregation pipelines
for channel stats and watch histories, and standardized RESTful responses.

Dependencies (from package.json):
- "express": "^5.2.1"          -> Web framework for routing and middleware.
- "mongoose": "^9.11.1"        -> MongoDB ODM for modeling and aggregation.
- "mongoose-aggregate-paginate-v2": "^1.1.5" -> Pagination plugin for aggregation queries.
- "bcrypt": "^6.0.0"           -> Secure password hashing with salt rounds.
- "jsonwebtoken": "^9.0.3"     -> Stateless Access Tokens and stateful Refresh Tokens.
- "cookie-parser": "^1.4.7"    -> Parse and set HTTP-only cookies.
- "cors": "^2.8.6"             -> Cross-Origin Resource Sharing.
- "dotenv": "^18.0.6"          -> Environment variable management.
- "multer": "^2.4.0"           -> Multipart/form-data handler for local disk storage.
- "cloudinary": "^2.11.0"      -> Cloud storage SDK for media hosting.

DevDependencies:

4. CORE ARCHITECTURAL PATTERNS & CONVENTIONS
================================================================================
1. Asynchronous Error Handling:
   Every controller and middleware function is wrapped in `asyncHandler`.
   There is no repetitive `try { ... } catch (err)` inside individual route handlers.
   If validation fails or a condition is violated, the code throws `new ApiError(code, message)`.
   `asyncHandler` intercepts the error and returns a formatted JSON response.

2. Consistent API Response Shape:
   Success responses always return:
   {
     "statusCode": 200 | 201,
     "data": <Object | Array>,
     "message": "<Human readable message>",
     "success": true
   }
   Error responses always return:
   {
     "success": false,
     "message": "<Error message>"
   }

3. Two-Step File Upload Flow:
   - Step A: Client sends multipart/form-data. Multer intercepts the file and saves it
     temporarily to `./public/temp/<filename>`.
   - Step B: Controller passes local path to `uploadOnCloudinary(localFilePath)`.
     Cloudinary uploads the media asset to the cloud and returns a secure HTTPS URL.
   - Step C: The temporary file on `./public/temp` is deleted via `fs.unlinkSync()`,
     regardless of whether the upload succeeded or failed.

4. Dual JWT Authentication & Refresh Cycle:
   - Access Token: Short expiration (e.g. 1 day), contains user identity (`_id`, `email`,
     `userName`, `fullName`). Passed via Cookie or `Authorization: Bearer <token>`.
   - Refresh Token: Long expiration (e.g. 10 days), contains only `_id`. Stored in DB
     on user document (`user.refreshToken`) and sent as an HTTP-only cookie.
   - Logout clears cookies and unsets `user.refreshToken` from the DB.
   - Token refresh matches the incoming refresh token against the DB record to prevent replay attacks.

5. UTILITY LAYER (CODE & LOGIC)

--- A. asyncHandler (src/utils/asyncHandler.js) ---
Code:
```javascript
const asyncHandler = (fn) => {
  return async (req, res, next) => {
    try {
      await fn(req, res, next);
    } catch (err) {
      res.status(err.statusCode || err.code || 500).json({
        success: false,
        message: err.message
      });
    }
  };
};
export { asyncHandler };
```
Purpose:
Eliminates boilerplate try/catch blocks. Catches both synchronous and rejected
asynchronous errors, automatically returning the HTTP status code (defaulting to 500)
and the error message.

--- B. ApiError (src/utils/ApiError.js) ---
Code:
```javascript
class ApiError extends Error {
  constructor(
    statusCode,
    message = "Something went wrong",
    errors = [],
    stack = ""
  ) {
    super(message);
    this.statusCode = statusCode;
    this.data = null;
    this.message = message;
    this.success = false;
    this.errors = errors;

    if (stack) {
      this.stack = stack;
    } else {
      Error.captureStackTrace(this, this.constructor);
    }
  }
}
export { ApiError };
```
Purpose:
Subclasses JavaScript's native Error to attach HTTP `statusCode`, custom error
details (`errors` array), and an operational `success = false` flag.

--- C. ApiResponse (src/utils/ApiResponse.js) ---
Code:
```javascript
class ApiResponse {
  constructor(statusCode, data, message = "Success") {
    this.statusCode = statusCode;
    this.data = data;
    this.message = message;
    this.success = statusCode < 400;
  }
}
export { ApiResponse };
```
Purpose:
Guarantees consistent JSON output structure for frontend consumption. Sets `success: true`
whenever `statusCode < 400`.

```javascript
import multer from "multer";

const storage = multer.diskStorage({
  destination: function (req, file, cb) {
    cb(null, "./public/temp");
  },
  filename: function (req, file, cb) {
    const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1E9);

  }
});

  storage: storage,
  limits: {
    fileSize: 1000000 * 1000 // 1000MB limit
  }
});
```

--- B. Cloudinary Service (src/services/cloudinary.js) ---
Code:
```javascript
import { v2 as cloudinary } from "cloudinary";
import fs from "fs";
import dotenv from "dotenv";

dotenv.config();

cloudinary.config({ 
  cloud_name: process.env.CLOUDINARY_CLOUD_NAME?.trim(), 
  api_key: process.env.CLOUDINARY_API_KEY?.trim(),
  api_secret: process.env.CLOUDINARY_API_SECRET?.trim()
});

const uploadOnCloudinary = async (localFilePath) => {
  try {
    if (!localFilePath) return null;

    cloudinary.config({ 
      cloud_name: process.env.CLOUDINARY_CLOUD_NAME?.trim(), 
      api_key: process.env.CLOUDINARY_API_KEY?.trim(),
      api_secret: process.env.CLOUDINARY_API_SECRET?.trim()
    });
    
    const uploadResult = await cloudinary.uploader.upload(localFilePath, {
      resource_type: "auto"
    });

    if (fs.existsSync(localFilePath)) {
      fs.unlinkSync(localFilePath);
    }

    return uploadResult;
  } catch (error) {
    console.error("Cloudinary upload error: ", error);
    if (fs.existsSync(localFilePath)) {
      fs.unlinkSync(localFilePath);
    }
    return null;
  }
};

export { uploadOnCloudinary };
```
Logic:
- Accepts a local file path.
- Configures Cloudinary (with `.trim()` to handle potential newline/space issues in `.env`).
- Uploads with `resource_type: "auto"` (supports images, videos, audio).
- Automatically removes the local file using `fs.unlinkSync(localFilePath)` on both success and failure.
- Returns the Cloudinary upload object (containing `.url`, `.secure_url`, `.duration`, etc.) or `null`.

Hooks & Methods:
1. `pre("save")`:
   ```javascript
   userSchema.pre("save", async function () {
     if (!this.isModified("password")) return;
     this.password = await bcrypt.hash(this.password, 10);
   });
   ```
   Hashes password with 10 salt rounds before saving only if the password field was modified.
2. `methods.isPasswordCorrect(password)`:
   Compares plaintext password with hashed password using `bcrypt.compare(password, this.password)`.

   Signs JWT containing `{ _id, email, userName, fullName }` using `process.env.ACCESS_TOKEN_SECRET`
   and expiry `process.env.ACCESS_TOKEN_EXPIRY`.
4. `methods.generateRefreshToken()`:
   Signs JWT containing `{ _id }` using `process.env.REFRESH_TOKEN_SECRET`
   and expiry `process.env.REFRESH_TOKEN_EXPIRY`.

9. MIDDLEWARES (AUTHENTICATION & VERIFICATION)
================================================================================

--- JWT Verification Middleware (src/middlewares/auth.middleware.js) ---
Export: `verifyJWT`
Code:
```javascript
import { asyncHandler } from "../utils/asyncHandler.js";
import jwt from "jsonwebtoken";
import { ApiError } from "../utils/ApiError.js";
import { User } from "../models/user.model.js";

export const verifyJWT = asyncHandler(async (req, _, next) => {
  try {
    const token =
      req.cookies?.accessToken ||
      req.header("Authorization")?.replace("Bearer ", "");

    if (!token) {
      throw new ApiError(401, "Unauthorized request");
    }

    const decodedToken = jwt.verify(token, process.env.ACCESS_TOKEN_SECRET);
    const user = await User.findById(decodedToken?._id).select("-password -refreshToken");

    if (!user) {
      throw new ApiError(401, "Invalid Access Token");
    }

    req.user = user;
    next();
  } catch (error) {
    throw new ApiError(401, error?.message || "Invalid Access Token");
  }
});
```
Flow:
1. Checks for access token in cookies (`req.cookies.accessToken`) or HTTP Authorization header (`Bearer <token>`).
2. Throws `ApiError(401, "Unauthorized request")` if token is missing.
3. Cryptographically verifies token with `process.env.ACCESS_TOKEN_SECRET`.
4. Fetches user from DB by decoded `_id`, stripping out `password` and `refreshToken`.
5. Attaches the clean user object to `req.user` and calls `next()`.

10. ALL 11 DONE & WORKING ROUTES (DETAILED SPECIFICATIONS)
================================================================================
Base Router URL: `/api/v1/users`
File: `src/routes/user.routes.js`
Controller: `src/controllers/user.controller.js`

--------------------------------------------------------------------------------
ROUTE 1: POST /api/v1/users/register
--------------------------------------------------------------------------------
- Purpose: Registers a new user account with profile avatar and optional cover image.
- Access: Public
- Middleware: `upload.fields([{ name: "avatar", maxCount: 1 }, { name: "coverImage", maxCount: 1 }])`
- Request Headers: `Content-Type: multipart/form-data`
- Request Body Fields:
  * `fullName` (String, Required)
  * `email` (String, Required)
  * `userName` (String, Required - also accepts `username` or `userName `)
  * `password` (String, Required)
- Files:
  * `avatar` (File, Required)
  * `coverImage` (File, Optional)
- Controller Execution Logic:
  1. Trims all text fields. If any required field is missing, throws `ApiError(400, "All fields are required")`.
  2. Queries DB: `User.findOne({ $or: [{ userName }, { email }] })`. If user exists, throws `ApiError(409, "User with email or username already exists")`.
  3. Checks `req.files?.avatar?.[0]?.path`. If absent, throws `ApiError(400, "Avatar is required")`.
  4. Calls `uploadOnCloudinary(avatarLocalPath)`. If upload fails, throws `ApiError(500, "Failed to upload avatar to Cloudinary")`.
  5. If `coverImageLocalPath` exists, uploads it to Cloudinary.
  6. Creates user: `User.create({ fullName, email, userName: userName.toLowerCase(), password, avatar: avatar.url, coverImage: coverImage?.url || "" })`.
  7. Mongoose `pre("save")` hook runs automatically, hashing `password` with bcrypt (10 rounds).
  8. Fetches created user document without `password` and `refreshToken`.
  9. Returns HTTP 201 with `ApiResponse(200, createdUser, "user registered successfully")`.

--------------------------------------------------------------------------------
ROUTE 2: POST /api/v1/users/login
--------------------------------------------------------------------------------
- Purpose: Authenticates existing user, returns access & refresh tokens, sets HTTP-only cookies.
- Access: Public
- Middleware: None
- Request Body (`application/json` or `urlencoded`):
  * `email` OR `userName` (String, Required)
  * `password` (String, Required)
- Controller Execution Logic:
  1. Validates that either `email` or `userName` is provided, and `password` is provided. Throws `ApiError(400)` if missing.
  2. Queries DB with `$or` matching lowercased username or email. If not found, throws `ApiError(404, "User does not exist")`.
  3. Validates password via `await user.isPasswordCorrect(password)`. If invalid, throws `ApiError(401, "Invalid user credentials")`.
  4. Calls internal helper `generateAccessAndRefreshToken(user._id)`:
     - Generates `accessToken` and `refreshToken`.
     - Assigns `user.refreshToken = refreshToken`.
     - Calls `user.save({ validateBeforeSave: false })` to store refresh token.
  5. Strips `password` and `refreshToken` from the user response object.
  6. Sets two cookies: `accessToken` and `refreshToken` with options `{ httpOnly: true, secure: process.env.NODE_ENV === "production" }`.
  7. Returns HTTP 200 with `ApiResponse(200, { user: loggedInUser, accessToken, refreshToken }, "User logged in successfully")`.

--------------------------------------------------------------------------------
ROUTE 3: POST /api/v1/users/logout
--------------------------------------------------------------------------------
- Purpose: Logs out the user by unsetting their refresh token from DB and clearing cookies.
- Access: Secured (requires valid JWT)
- Middleware: `verifyJWT`
- Request Headers/Cookies: Cookie `accessToken` or Header `Authorization: Bearer <token>`
- Controller Execution Logic:
  1. Runs `User.findByIdAndUpdate(req.user._id, { $unset: { refreshToken: 1 } }, { new: true })`.
  2. Clears `accessToken` and `refreshToken` cookies with `{ httpOnly: true, secure: process.env.NODE_ENV === "production" }`.
  3. Returns HTTP 200 with `ApiResponse(200, {}, "User logged out successfully")`.

--------------------------------------------------------------------------------
ROUTE 4: POST /api/v1/users/refresh-token
--------------------------------------------------------------------------------
- Purpose: Exchanges an existing valid refresh token for a fresh access & refresh token pair.
- Access: Public / Token-based
- Middleware: None
- Request: Reads `req.cookies.refreshToken || req.body.refreshToken`
- Controller Execution Logic:
  1. If no refresh token provided, throws `ApiError(401, "Unauthorized request")`.
  2. Verifies token with `jwt.verify(refreshTokenFromUser, process.env.REFRESH_TOKEN_SECRET)`.
  3. Finds user by decoded `_id`. If not found, throws `ApiError(401, "Invalid Refresh Token")`.
  4. Checks if stored `user.refreshToken !== refreshTokenFromUser`. If unequal (e.g. token was rotated or user logged out), throws `ApiError(401, "Invalid Refresh Token")`.
  5. Calls `generateAccessAndRefreshToken(user._id)` to issue new token pair and save new refresh token in DB.
  6. Sets cookies `newAccessToken` and `newRefreshToken`.
  7. Returns HTTP 200 with `ApiResponse(200, { user, newAccessToken, newRefreshToken }, "User logged in successfully")`.

--------------------------------------------------------------------------------
ROUTE 5: POST /api/v1/users/change-password
--------------------------------------------------------------------------------
- Purpose: Allows an authenticated user to update their account password.
- Access: Secured
- Middleware: `verifyJWT`
- Request Body: `{ "oldPassword": "...", "newPassword": "..." }`
- Controller Execution Logic:
  1. Finds user document by `req.user._id`.
  2. Verifies `await user.isPasswordCorrect(oldPassword)`. If false, throws `ApiError(401, "Invalid Current Password")`.
  3. Assigns `user.password = newPassword`.
  4. Calls `await user.save({ validateBeforeSave: false })`.
  5. Mongoose `pre("save")` hook triggers and hashes `newPassword`.
  6. Returns HTTP 200 with `ApiResponse(200, {}, "Password changed successfully")`.

--------------------------------------------------------------------------------
ROUTE 6: GET /api/v1/users/current-user
--------------------------------------------------------------------------------
- Purpose: Returns the currently authenticated user's profile.
- Access: Secured
- Middleware: `verifyJWT`
- Controller Execution Logic:
  1. `verifyJWT` has already attached the sanitized user object to `req.user`.
  2. Returns HTTP 200 with `ApiResponse(200, req.user, "Current user fetched successfully")`.

--------------------------------------------------------------------------------
ROUTE 7: PATCH /api/v1/users/update-account
--------------------------------------------------------------------------------
- Purpose: Updates user's textual profile info (`fullName` and `email`).
- Access: Secured
- Middleware: `verifyJWT`
- Request Body: `{ "fullName": "...", "email": "..." }`
- Controller Execution Logic:
  1. Checks that both `fullName` and `email` exist. If missing, throws `ApiError(400, "Full name and email are required")`.
  2. Runs `User.findByIdAndUpdate(req.user._id, { $set: { fullName, email } }, { new: true }).select("-password -refreshToken")`.
  3. Returns HTTP 200 with `ApiResponse(200, user, "User details updated successfully")`.

--------------------------------------------------------------------------------
ROUTE 8: PATCH /api/v1/users/update-avatar
--------------------------------------------------------------------------------
- Purpose: Replaces user's profile avatar with a newly uploaded image file.
- Access: Secured
- Middleware: `verifyJWT`, `upload.single("avatar")`
- Request: `multipart/form-data` with file field `avatar`.
- Controller Execution Logic:

12. KEY EDGE CASES, QUIRKS, AND IMPLEMENTATION GOTCHAS
================================================================================
When another AI or developer modifies this codebase, take note of these specific details:

1. Double-dot Filename:
   The multer middleware file is named `src/middlewares/multer..middleware.js` (with two dots).
   Imports currently refer to `../middlewares/multer..middleware.js`. Do not break this import path.

2. Route Path Definition in user.routes.js:
   Line 49 is written as: `router.route("c/:username").get(verifyJWT, getUserChannelProfile)`.
   Notice there is no leading slash (`"c/:username"` instead of `"/c/:username"`).
   In Express router, both resolve to `/api/v1/users/c/:username`.

3. Case Sensitivity in userName:
   `userName` is saved in lowercase in DB: `userName: userName.toLowerCase()`.
   Controllers support flexible input keys: `req.body.userName || req.body["userName "] || req.body.username`.

4. Refresh Token Verification:
   The `refreshAccessToken` controller verifies that the incoming token matches `user.refreshToken` in the DB.
   If a user has logged out (which executes `$unset: { refreshToken: 1 }`), `refreshAccessToken` will reject with 401.

5. Cookie Names in Refresh Token Route:
   Notice in `refreshAccessToken`, the controller sets cookies named `newAccessToken` and `newRefreshToken`:
   `res.cookie("newAccessToken", ...).cookie("newRefreshToken", ...)`.
   In `loginUser`, the cookies are named `accessToken` and `refreshToken`.
   Be aware of this distinction when managing client-side authentication cookies.

6. Bcrypt Pre-save Hook:
   The `userSchema.pre("save")` hook checks `if (!this.isModified("password")) return;`.
   When updating tokens (in `generateAccessAndRefreshToken`) or other fields via `.save()`, always pass
   `{ validateBeforeSave: false }` or ensure `password` is untouched so passwords are not re-hashed.

7. Cloudinary Upload Cleanup:
   `uploadOnCloudinary` guarantees that local files in `./public/temp` are removed via `fs.unlinkSync()`
   both when upload succeeds AND when upload fails in the `catch` block.

13. GUIDE FOR FUTURE AI / DEVELOPERS (HOW TO EXTEND THIS PROJECT)
================================================================================
To implement any new feature or module in this codebase, follow this standard pattern:

1. Model:
   Create `src/models/<name>.model.js`.
   Import `mongoose, { Schema } from "mongoose"`.
   Export named model: `export const <ModelName> = mongoose.model("<ModelName>", schema)`.

2. Controller:
   Create `src/controllers/<name>.controller.js`.
   Import `asyncHandler`, `ApiError`, `ApiResponse`, and required models.
   Wrap each handler function with `asyncHandler(async (req, res) => { ... })`.
   Throw `new ApiError(statusCode, message)` on validation or business errors.
   Return `res.status(code).json(new ApiResponse(code, data, message))`.

3. Router:
   Create `src/routes/<name>.routes.js`.
   Import `Router` from `"express"` and your controller handlers.
   Protect sensitive routes with `verifyJWT`.
   Use `upload.single(...)` or `upload.fields(...)` if handling file uploads.
   Export default `router`.

4. App Mount:
   In `src/app.js`:
   `import <name>Router from "./routes/<name>.routes.js";`
   `app.use("/api/v1/<name>", <name>Router);`
